Where these numbers come from: a Logistic Regression model, trained on this project's staged/composite outcome target (Phase 5a-6), scores every candidate as intercept + Σ coefficient × feature value — shown here as the compatibility index. Positive means the model favours this pairing; 0 is its decision boundary; higher is stronger. The "why" bars show each feature's exact contribution to that number for this pairing: coefficient × (this pair's value − the training-set average) — the closed-form SHAP value for a linear model, not an approximation. existing_rule_score is deliberately left out, because it can't be computed for a person who isn't already in NoCatch's historical data. As a brand-new profile, you'd be a cold-start user in the real system (Blueprint §13) — routed to the content-similarity fallback rather than this full model; this demo runs the full model anyway, for illustration.

Why an index and not a probability: this model separates the training data almost perfectly (held-out ROC-AUC ≈ 0.9995) — expected, since the composite target it predicts was itself built from earlier-stage models trained on very similar features, so recovering it from these same 10 inputs is closer to reconstructing a formula than discovering a hard pattern. In practice that means the model's predicted probability saturates to ~100% for almost every strongly-favoured candidate, hiding real differences between them. The raw index shown here doesn't saturate, so it stays genuinely comparable between candidates — this is flagged plainly rather than shown as a headline accuracy number.
